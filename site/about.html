About

A high-school sophomore in Las Vegas built this.

Not a company, not a team, not a startup in stealth. One person, working in the open under Apache-2.0. That is stated here because the alternative — letting the plural pronouns on a project site imply an organisation — would be the first dishonest thing on a site whose entire argument is that this field’s published numbers cannot be trusted.

01The project

What it is.

Palimpsest is an open-world bitemporal claim-interval memory engine for AI agents. Facts are stored as (entity, predicate) → version chain, and a new value closes the previous interval instead of coexisting with it, so “what is true now” is a key lookup rather than a similarity search. Two time axes are kept apart: valid time, closed by a change, and transaction time, closed by a correction.

A palimpsest is a manuscript that was scraped and rewritten, where the earlier text stays legible underneath. The way palimpsests are actually read is multispectral imaging: light the sheet at wavelengths the eye cannot use, and the erased undertext comes back. That is the same operation as timeline() — nothing here is deleted, only closed, and the earlier versions stay readable beneath the current one.

02Status

Alpha. The API may change.

The test suite is green on Python 3.11 through 3.13 and the stored schema is SQLite with a Postgres-portable shape, but this is an alpha and the public surface is not frozen. If you build on it, pin the version.

  • Licence: Apache-2.0, for the code and for everything on this site.
  • Distribution: PyPI, source on GitHub.
  • Support: GitHub issues. There is no support contract and no company behind one.
  • Funding: none. Nothing on this site is sponsored and no result on it was paid for.

What it is not

It is not a hosted service, it is not a vector database replacement for general document retrieval, and it is not a system that will beat a strong retriever on questions that have no assertable fact in them. The limits are enumerated on the docs page, and the benchmark it loses is on the front of the benchmarks page rather than at the bottom.

03Numbers

How this site handles its own results.

In a field where self-reported scores do not survive independent measurement, the only thing worth publishing is the measurement somebody else can repeat. So every number on this site is printed with the scope of the run that produced it, and the raw per-question records for each one are in the repository.

  • One process, one answering model, one judge that is not the answering model, the unmodified standard Mem0 judge prompt, the same 1,024-token budget for every system, and the identical extracted claims shared across every fact-based system.
  • Confidence intervals are printed next to the accuracy, not omitted when they are inconvenient.
  • The benchmark this engine loses gets a section of its own, and the categories it loses inside benchmarks it wins are named.
  • Numbers measured before a bug was fixed are withdrawn rather than kept because they were higher.

Read this with the number

On LongMemEval this engine is first overall in our harness — 0.589, [0.544, 0.633], against 0.553 for hybrid_rag — but in both LongMemEval tables the confidence interval overlaps the runner-up, so the margin over second place is not statistically significant. The margin over BM25 and below is. And we lose LoCoMo.

Where it loses

On LoCoMo, all 10 conversations, 468 questions: full_context wins at 0.549 on 23,604 tokens. bm25 at 0.417 and palimpsest at 0.408 are a statistical tie.

Nine defects found in this engine’s own audit are published, including one where it could see the future and inflate its own results, and one whose fix lowered the LoCoMo score. The lower number is the one reported. The audit is here, and the reason all of this is necessary is on the field page.

04Why

Why a student built this rather than a lab.

The idea is not novel. Bitemporal modelling is decades old in databases, and the contribution here is narrow: applying it to agent memory as the primary key rather than as an audit log, and doing the open-world predicate canonicalization that has to work before any of it fires. That is a small enough problem for one person to actually finish, and finishing it honestly is the part that turned out to be scarce.

Being one person is a real limitation and it is not being dressed up as an advantage. No second pair of eyes reviews the code by default, so the audit was run adversarially instead, with agents whose job was to refute each other. No organisation stands behind the numbers, so the raw per-question records are published for every table. The confidence intervals overlap, so the site says the margin is not significant instead of rounding the claim up.

If a number here is wrong, the fastest way to prove it is to run the harness. Everything needed to do that — the datasets, the seeds, the prompts and the commands — is in the methodology, and corrections are welcome as issues on GitHub.
