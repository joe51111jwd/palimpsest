Memory for AI agents

A new fact closes the old one instead of sitting next to it.

Facts are stored as (entity, predicate) → version chain. Writing a new value closes the previous interval, so “what is true now” is a key lookup rather than a similarity search — and it cannot be wrong about which value is newer.

01The problem

Ask “where do I work?” after two job changes.

The same three utterances are in both stores. On the left is what a vector store hands the model. On the right is what Palimpsest hands it.

Vector store → context 3 chunks
“I just started at Initech.” match
“I work at Globex now.” match
“First week at Cyberdyne.” match
Three contradictory employers, no ordering. Every one of them is an excellent semantic match for the question, and nothing in the text marks any of them as expired. The model picks one — often the wrong one. Bolting a timestamp onto a chunk does not fix this: the stale chunk still scores well and still gets retrieved.
Palimpsest → context 1 current value
user · employer · version chain, valid time
Cyberdyne current 2024-01-08 → open
Globex superseded 2022-08-15 → 2024-01-08
Initech superseded 2021-03-02 → 2022-08-15
One current value; the rest dated and labelled superseded. Nothing was deleted — the earlier versions are still readable underneath, which is what makes as_of= time travel possible. The engine did not need a model to work out which one is newer.

Illustrative example data. The layout is the real component: current on top at full ink, superseded layers stepped in beneath it in recovered-undertext amber.

02Mechanism

Store claims, not chunks, and put the validity interval in the primary key.

A new value closes the previous interval instead of coexisting with it. Contradiction resolution costs no LLM call. Retrieval needs no LLM at all; one is used to extract facts on write, and optionally to adjudicate predicates never seen before.

The ledger
(entity, predicate) ──► version chain

  (user, city): [ New York City | 2023-01-01 → 2023-04-11 ]
                [ Austin        | 2023-04-11 → open       ]  ← current
python
from palimpsest import Memory

mem = Memory()
mem.ingest(messages)

mem.recall("Where do I live?")
# current value only

mem.recall("Where did I live?", as_of=LAST_YEAR)
# time travel

mem.timeline("user", "city")
# every version, in order
Two time axes, kept separate
Valid time
When a fact was true in the world. Closed by a change — “I moved to Boston.” The past record stays true of the past.
Transaction time
When the store was told. Closed by a correction — “I was never at Globex, I misspoke.” It was never true at all.

They are not the same fact and are not stored the same way. Nothing is ever deleted, only closed.

Why a cosine threshold cannot canonicalize predicates

The hard part is not the ledger. It is making lives_in and city land on the same key, or supersession never fires. The obvious fix — embed the predicate name, merge above a threshold — is measurably backwards:

Name-only cosine similarity between predicates
pair cosine relationship
lives_in ~ city 0.136 the same thing
favorite_food ~ least_favorite_food 0.842 opposite things
birth_year ~ birth_city 0.735 different things

The ordering is inverted: synonyms average 0.287, traps 0.495, and all six trap pairs land in the top 3 of their counterpart. Embedding the observed values flips the ordering (synonyms 0.302, traps 0.101) but is still not thresholdable. So similarity is used as a shortlist only — the correct cluster is in the top-20 for 100% of predicates — an LLM adjudicates, and deterministic guards (polarity, value-type, head-noun, role-suffix) hold a veto they can exercise but never override.

03Measured

First on LongMemEval-S, and the margin over second place holds up.

One process, one answering model, a judge separate from the answerer, the unmodified standard Mem0 judge prompt, the same 1,024-token budget for every system, and the identical extracted claims shared across every fact-based system. Every question judged in its own call — batching the judge let one system’s answers move another system’s verdicts, which an outside audit caught and which is now fixed.

Read this with the number

The lead is category-shaped, not general. Against hybrid_rag it is +7.0 on knowledge-update, +11.5 on multi-session and +4.0 on temporal — the categories where the answer depends on which version of a fact is current. On single-session recall the two are level and bm25 beats both, and on single-session preference we score 0.167, the worst number on the board. And we lose LoCoMo.

What holds up when the haystack is realistic

On the knowledge-update slice of that run — the category this design exists for — Palimpsest scores 0.736 against 0.708 for hybrid_rag, 0.639 for bm25 and 0.389 for full_context at 31,531 tokens. The sharper finding is the delta when the distractors are taken away and put back:

system change

Where it loses

On LoCoMo, all 10 conversations, 468 questions: full_context wins at 0.549 on 23,604 tokens. bm25 at 0.417 and palimpsest at 0.408 are a statistical tie. The fact-layer baselines — mem0_style 0.237 and zep_style 0.278 — sit about 17 points below plain BM25 on the identical claims.

04The field

Published numbers in agent memory do not reproduce.

This is verified from primary sources, and it is the reason every number above is stated with its interval and its losses.

Self-reported vs. independently measured, LongMemEval
system self-reported measured by third parties
Mem0 94.4 36–67
Supermemory 95 58.4
Zep 90.2 38–64
LightMem the only system whose self-report reproduces

An embedding swap erases the claim

MemDelta (arXiv 2606.29914): Mem0’s advertised +11pp over RAG becomes −1.2pp when the RAG baseline gets a decent embedding model.

Construction can destroy accuracy

The LightMem reproduction (arXiv 2607.29104) held retrieval at oracle and found memory construction cost 11.3 points against naive RAG.

The labels are wrong

The LoCoMo category labels used by the Mem0 → Memobase → Backboard lineage are wrong on 3 of 4 categories.

The cited release is deprecated

The LongMemEval release everyone cites was deprecated on 2025-09-19 and replaced with a cleaned one.

There is no leaderboard

No public leaderboard for agent memory exists anywhere. Every vendor publishes its own number, measured its own way.

Including against ourselves

Nine defects found in our own engine are published — including one where it could see the future and inflate its own results, and one whose fix lowered our LoCoMo score.

05Install

CPU-only, three dependencies, no service to run.

numpy, model2vec, tiktoken. No torch, no GPU, no external service. SQLite storage with a Postgres-portable schema; nothing is ever deleted, only closed.

06Who built it

Independent, and Apache-2.0.

No product here can be embarrassed by a result, which is why the losses, the margins that fail a significance test and the defects found by outside audit are on the site instead of in a footnote. In a field where self-reported numbers do not survive independent measurement, the only thing worth publishing is the measurement anyone else can repeat.

Palimpsest

An open-world bitemporal claim-interval memory engine for AI agents. A palimpsest is a manuscript scraped and rewritten, where the earlier text stays legible underneath. So is this.
