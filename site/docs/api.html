02Memory

Memory

The public API. It owns an embedder, a canonicalizer, the ledger, the episodic index and a retriever, and it is the only object most callers touch. Constructing one with no arguments is valid and does something useful: the seed synonym groups (concepts §06) mean the common attributes canonicalize correctly with no model configured at all.

signature
Memory(
    *,
    extractor: Extractor | None = None,
    embedder: Embedder | None = None,
    adjudicator: PredicateAdjudicator | None = None,
    index_messages: bool = True,
)
Constructor parameters — all keyword-only
parameter default meaning
extractor None Turns messages into claims on ingest. With none configured, ingest() extracts nothing unless you pass claims= yourself.
embedder default_embedder() Process-wide shared static embedder. Loading the model twice is wasteful, so pass the shared one rather than a second instance.
adjudicator None Decides whether a novel predicate means the same as an existing one. Guards may veto what it proposes; nothing can force a merge it declines.
index_messages True Index the raw utterances for the hybrid tier. Setting this False gives you a pure fact ledger and removes tier 3 entirely.

Attributes

  • mem.ledger — the Ledger. Atoms, chains, statistics.
  • mem.canon — the Canonicalizer. Entities, predicates, aliases, the merge log.
  • mem.index — the EpisodicIndex over raw messages.
  • mem.retriever — the Retriever that plans and fuses the three tiers.
  • mem.embedder — check mem.embedder.backend to confirm you are not on the hashing fallback.
03ingest

Memory.ingest

Folds a batch of messages into memory. Messages are indexed for the hybrid tier, claims are extracted (or supplied), relation bindings are resolved so that “my sister” and “Maria” land on one entity from the first write, and each claim is applied to the ledger.

Each claim's transaction time is the timestamp of the message named by its source_id, so the ingest order does not decide when the store learned something — the transcript does. A claim whose source_id matches no message in the batch falls back to the latest timestamp seen so far.

signature
ingest(
    messages: Sequence[Message],
    *,
    claims: Iterable[Claim] | None = None,
) -> IngestResult

claims= is a first-class path, not a test hook: it lets extraction happen once, in one big cached batch, instead of inside the ingest loop. It is what the benchmark harness uses, and it is what makes the examples on this site deterministic and offline.

python
from datetime import datetime
from palimpsest import Memory, Message
from palimpsest.types import Claim

messages = [
    Message(session_id="s1", speaker="user", role="user", msg_id="m1",
            text="I live in New York City.", timestamp=datetime(2023, 1, 1, 12, 0)),
    Message(session_id="s1", speaker="user", role="user", msg_id="m2",
            text="Just moved to Austin!",    timestamp=datetime(2023, 4, 11, 12, 0)),
]
claims = [
    Claim(entity="user", predicate="city",     value="New York City",
          source_text=messages[0].text, source_id="m1"),
    Claim(entity="user", predicate="lives_in", value="Austin",
          source_text=messages[1].text, source_id="m2"),
]

mem = Memory()
print(mem.ingest(messages, claims=claims))

# IngestResult(messages=2, claims=2, atoms_created=2, supersessions=1,
#              retractions=0, noops=0, predicates_minted=1,
#              predicates_aliased=2, latency_ms=0.09)
#              — the timing is from one laptop; everything else is exact

One supersession, one canonical predicate from two surface forms. If predicates_minted climbs with every ingest while supersessions stays at zero, your synonyms are not merging and the ledger is quietly degrading into a fact list — that pair of counters is the cheapest health check there is.

04recall

Memory.recall

Plans the query, runs the three tiers, and renders a prompt-ready block. It calls no model: pure Python and numpy.

signature
recall(
    query: str,
    *,
    k: int = 8,
    as_of: datetime | None = None,
    known_at: datetime | None = None,
    token_budget: int = 1024,
) -> Recall
recall() parameters
parameter default meaning
query — The question, in natural language. Entities are resolved from name mentions and first-person pronouns; predicates by embedding the question against the canonical predicates this store actually learned. No hardcoded vocabulary.
k 8 Target number of structured facts. A soft target: the graph tier stops once k is reached, and the final fact list is capped at max(k, 24) before rendering.
as_of None Valid time. “What was true on this date?” Defaults to the latest message timestamp the store has seen — i.e. now. §05.
known_at None Transaction time. “What had the store been told by this date?” Independent of as_of. §05.
token_budget 1024 Hard ceiling on Recall.context, enforced after packing rather than estimated. The fact block gets a fraction of it that depends on how confidently the question resolved to a predicate; excerpts get the rest.
python
r = mem.recall("Where do I work?")

print(r.context)        # the block you paste into a prompt
print(r.n_tokens)               # 117
print(r.resolved_predicates)    # ['employer', 'city']
print(r.resolved_entities)      # ['user']
print(r.tier_counts)            # {'interval': 2, 'graph': 1, 'hybrid': 3}
print(round(r.latency_ms, 2))   # 1.27

for rf in r.facts:
    print(rf.tier, rf.score, rf.fact.value)

# interval 3.0 Pied Piper
# interval 3.0 Austin
# graph 1.5 penicillin
Recall.context
KNOWN FACTS (current, verified true as of the latest information):
  - The user's city: Austin   [since 2023-04-11]

RELEVANT CONVERSATION EXCERPTS:
  [2023-02-03] user: I work at Globex.
  [2023-04-11] user: Just moved to Austin!
  [2023-06-02] user: My new employer is Pied Piper.
  [2023-03-09] user: I'm allergic to penicillin.

When as_of is set, the block is prefixed with [Memory as of YYYY-MM-DD]. On a historical question the superseded values are emitted first, under EARLIER VALUES (no longer true — superseded):, because on such a question they are the answer.

A non-empty store never returns an empty context

The hybrid tier is unconditional. If the question resolves to no predicate at all you still get excerpts, never an empty string. An earlier version early-returned nothing when its keyword parser failed to fire; that scored well on a synthetic abstention metric and catastrophically on real paraphrases.

05as_of / known_at

The two bounds are different questions, and conflating them leaks the future.

as_of bounds valid time: what was true in the world on that date. known_at bounds transaction time: what the store had been told by that date. They are independent, and you usually want both.

Here is why it matters. A user says in September, “I moved to Austin back in April.” The Austin atom's valid time starts in April; its transaction time starts in September. Now ask, in June, where they live.

python
messages = [
    Message(session_id="s", speaker="user", role="user", msg_id="m1",
            text="I live in New York City.",
            timestamp=datetime(2023, 1, 1, 12, 0)),
    Message(session_id="s", speaker="user", role="user", msg_id="m2",
            text="I moved to Austin back in April.",
            timestamp=datetime(2023, 9, 1, 12, 0)),          # told in September
]
claims = [
    Claim(entity="user", predicate="city", value="New York City",
          source_text=messages[0].text, source_id="m1"),
    Claim(entity="user", predicate="city", value="Austin",
          valid_from=datetime(2023, 4, 11, 12, 0),           # true since April
          source_text=messages[1].text, source_id="m2"),
]
mem = Memory()
mem.ingest(messages, claims=claims)

june = datetime(2023, 6, 1, 12, 0)

r = mem.recall("Where do I live?", as_of=june)
print([rf.fact.value for rf in r.facts])
# ['Austin']        <- true in June, but nobody had said so yet

r = mem.recall("Where do I live?", as_of=june, known_at=june)
print([rf.fact.value for rf in r.facts])
# ['New York City'] <- what the store could actually have answered in June

Both answers are correct. They answer different questions:

  • Historical truth. as_of alone. “Where did this person live in June?” Austin. Use this for reporting on the past with everything you now know.
  • Historical belief. as_of and known_at. “Answer as the assistant could have on 1 June.” New York City. Use this for auditing an old answer, for replaying a conversation, and for any benchmark that asks a question at a point in the transcript.

This distinction was a defect in this engine, and fixing it cost score

The excerpt tier had always filtered transaction time — a message the store had not received yet is not retrievable. The fact tier filtered valid time only. So a question asked in June could be answered from a fact the store first heard in September, while the context header still claimed to be “as of June”. On LongMemEval that produced apparent wins where the gold answer reached this system and no baseline, because no baseline can see the future either. The defect log →

Passing a question's own timestamp

If you are answering a question that occurs at a point in a transcript, pass that timestamp as both bounds. That is almost always what you mean, and it is what the harness does for every system it measures.

python
asked_at = question.timestamp
r = mem.recall(question.text, as_of=asked_at, known_at=asked_at)

known_at reaches three places: the interval tier drops atoms whose tx_from is later than the bound; a closure the store had not yet learned is ignored, so the earlier value stays open; and a supersession the store had not yet learned cannot be used to suppress an excerpt as stale. The last one matters — without it, evidence disappears from the context on the strength of a fact that had not arrived yet.

One caveat after a reload

The closed_tx stamp — when the store learned that an interval had ended — has no column in the SQLite schema and is not restored by SQLiteStore.load(). Valid-time queries round-trip exactly; known_at queries against a reloaded store do not see the pre-closure belief state. Keep a Memory in process for belief-time work, or reconstruct it by re-ingesting. §11.

06facts

Memory.facts

Everything the store holds, as Facts, sorted by (entity, predicate, valid_from). This is the direct ledger read: no query planning, no ranking, no token budget.

signature
facts(
    *,
    entity: str | None = None,
    as_of: datetime | None = None,
    include_history: bool = False,
) -> list[Fact]
facts() parameters
parameter effect
entity Restrict to one canonical entity, resolved through the alias table. This is a plain alias hit, not the write path’s resolution: a name the store has no alias for resolves to None, and facts() then applies no filter at all and returns everything. First-person forms are the trap — "me" and "I" collapse to user when a claim is written but are not registered as aliases, so facts(entity="me") filters nothing. Pass the canonical name.
as_of Valid-time slice: every value true on that date. There is no known_at here — use recall() for belief-time bounds.
include_history Return every believed atom on every key, superseded ones included. Overrides as_of.
python
for fact in mem.facts():
    print(fact.as_line())

# You — allergic to: penicillin  (current, since 2023-03-09)
# You — city: Austin  (current, since 2023-04-11)
# You — employer: Pied Piper  (current, since 2023-06-02)

len(mem.facts())                          # 3 — current values only
len(mem.facts(include_history=True))      # 5 — every version ever held

# a valid-time slice: only what was true that day
[(f.predicate, f.value)
 for f in mem.facts(entity="user", as_of=datetime(2023, 3, 1, 12, 0))]
# [('city', 'New York City'), ('employer', 'Globex')]

[(f.predicate, f.value)
 for f in mem.facts(entity="user", as_of=datetime(2023, 5, 1, 12, 0))]
# [('allergic_to', 'penicillin'), ('city', 'Austin'), ('employer', 'Globex')]
07timeline

Memory.timeline

Every version of one attribute, oldest first — the palimpsest view. If either name is unknown the result is an empty list, not an error.

The predicate goes through the alias table, so any surface form that canonicalized onto the key works: timeline("user", "lives_in") and timeline("user", "city") return the same chain. The entity is a plain alias hit and is stricter — timeline("me", "city") returns [], because me collapses to user on the write path but is not stored as an alias. Pass the canonical name.

Corrected atoms are absent: the chain returns believed atoms only.

signature
timeline(entity: str, predicate: str) -> list[Fact]
python
for fact in mem.timeline("user", "city"):
    print(fact.as_line())

# You — city: New York City  (was true 2023-01-01 to 2023-04-11, superseded)
# You — city: Austin  (current, since 2023-04-11)

# the raw fields, if you are rendering it yourself
for fact in mem.timeline("user", "city"):
    print(fact.value, fact.valid_from, fact.valid_to, fact.is_current)
user · city · what timeline() returns, rendered
Austin current 2023-04-11 → open
New York City superseded 2023-01-01 → 2023-04-11
timeline() returns these oldest-first; the component shows them current-first.
08correct

Memory.correct

Retracts a stored fact as never-having-been-true — a transaction-time close. This is not supersession: the atom stops being returned for any as_of, and whatever it superseded reopens to cover the gap. Use it for “I was never at Globex, I misspoke”, never for “I moved”.

Returns the number of atoms retracted. Matching is on the value, case-insensitively and exactly; every believed atom on the key holding that value is retracted.

signature
correct(entity: str, predicate: str, value: str) -> int
python
# chain: Initech (2021-03-02), Globex (2022-08-15), Cyberdyne (2024-01-08)

mem.correct("user", "employer", "Globex")      # -> 1

for fact in mem.timeline("user", "employer"):
    print(fact.as_line())

# You — employer: Initech    (was true 2021-03-02 to 2024-01-08, superseded)
# You — employer: Cyberdyne  (current, since 2024-01-08)

mem.correct("user", "employer", "Globe")       # -> 0, nothing changed

Check the return value

A correction that matches nothing corrects nothing and returns 0. An earlier version treated a missed value lookup as “match everything”, so correct("user", "city", "New York") against a stored "New York City" wiped the entire chain and reported success. The transaction time used is the latest message timestamp the store has seen, falling back to datetime.now() for an empty store.

10Dataclasses

The value objects.

All in palimpsest.types. Message, Claim and Fact are frozen; the rest are plain dataclasses. Three type aliases are exported alongside them: Polarity = "positive" | "negative", Cardinality = "single" | "multi", and ValueType = "date" | "number" | "person" | "place" | "org" | "boolean" | "text". The sentinel OPEN is None and means “still open”.

Message — one utterance, with real wall-clock time

python
Message(
    session_id: str,
    speaker: str,
    text: str,
    timestamp: datetime,
    msg_id: str = "",
    role: str = "",       # "user" / "assistant" when the source distinguishes them
)
msg.is_user        # property: True unless role == "assistant"

Give every message a distinct msg_id. It is how a claim is attributed to the utterance that asserts it, how transaction time is assigned on ingest, how stale excerpts are suppressed, and the unique key in the persisted messages table. timestamp must be a real datetime; the entire engine is built on it.

Claim — what an extractor emits

python
Claim(
    entity: str,
    predicate: str,                          # RAW surface form; canonicalized later
    value: str,
    polarity: Polarity = "positive",
    cardinality: Cardinality = "single",
    value_type: ValueType = "text",
    valid_from: datetime | None = None,      # None -> the source message's timestamp
    confidence: float = 1.0,
    source_text: str = "",
    source_id: str = "",               # the msg_id that asserts it
)
claim.normalized()   # -> Claim with entity/value stripped and
                     #    predicate lowercased, spaces -> underscores
  • polarity="negative" closes an interval without opening a successor — “I don't have a cat anymore”, not “I moved to Boston”. It creates no atom.
  • cardinality is a vote, not an instruction. The key decides. Concepts §05.
  • value_type left at "text" is inferred from the value (date, number, boolean, else text). It feeds the type-compatibility guard, which is what stops birth_year merging with birth_city.
  • valid_from is when the fact became true in the world. Set it whenever the text pins one down — that is what makes a retroactive insert retroactive.

Fact — the id-free public view of an atom

python
Fact(

    predicate: str,
    value: str,
    valid_from: datetime,
    valid_to: datetime | None,     # None = still true
    is_current: bool,
    source_text: str,
    source_id: str,
    confidence: float = 1.0,

fact.as_line(with_dates=True) -> str

# You — city: Austin  (current, since 2023-04-11)
# You — city: New York City  (was true 2023-01-01 to 2023-04-11, superseded)
# with_dates=False:  "You — city: Austin"

as_line() renders user and you as “You” and turns underscores into spaces. is_current is the raw ledger property — the interval is open — and is not re-evaluated under a known_at bound.

Atom — the stored interval

Exported for inspection and for anyone writing their own persistence layer. You do not construct these; the ledger does.

python
Atom(
    idx: int,                          # position in Ledger.atoms; the row id
    entity_id: int,
    predicate_id: int,
    value_id: int,
    entity: str, predicate: str, value: str,   # surface forms, for rendering
    valid_from: datetime,
    valid_to: datetime | None = None,  # None = still true
    tx_from: datetime | None = None,
    tx_to: datetime | None = None,     # None = still believed
    source_text: str = "", source_id: str = "",
    value_type: ValueType = "text",
    cardinality: Cardinality = "single",
    confidence: float = 1.0,
    predecessor: int | None = None,
    successor: int | None = None,
    access: int = 0,
    closed_tx: datetime | None = None, # when we LEARNED valid_to
)

atom.is_open                       # valid_to is None
atom.is_believed                   # tx_to is None
atom.key                           # (entity_id, predicate_id)
atom.valid_at(when, known_at=None) # -> bool
atom.believed_at(when)             # -> bool

valid_at(when, known_at) is where the two axes meet: if the interval was closed by something the store learned after known_at, the closure is ignored and the atom is treated as still open. That one branch is the whole “what did we believe last Tuesday” capability.

11SQLiteStore

SQLiteStore

Durable storage for the ledger and the message index. The schema is deliberately boring SQL with no SQLite-specific types, because a storage primitive that only exists inside one Python process is a demo. The same DDL runs on Postgres with two substitutions (INTEGER PRIMARY KEY → BIGSERIAL, TEXT timestamps → TIMESTAMPTZ), which is the intended production path.

signature
SQLiteStore(path: str | Path = ":memory:")

store.save(memory)  -> int    # atoms written; idempotent
store.load(memory)  -> int    # atoms restored, into a FRESH Memory
store.close()       -> None
python
from palimpsest import Memory, SQLiteStore

store = SQLiteStore("memory.db")
store.save(mem)                    # -> 5

restored = Memory()
store.load(restored)               # -> 5
print(restored.recall("Where do I live?").context)
store.close()

Tables

  • entities — id, name, JSON alias list.
  • predicates — id, name, JSON alias list, JSON value-type counts.
  • atoms — one row per interval. Append-only: the sole mutation is closing valid_to or tx_to. A value is never overwritten and a row is never deleted.
  • messages — the raw utterances, unique on msg_id.

Indexes exist for the three access patterns that matter:

  • current value of a key — (entity_id, predicate_id, valid_to)
  • value at a past time — (entity_id, predicate_id, valid_from)
  • everything about an entity — (entity_id)

That append-only discipline is what makes the store auditable: every value the system ever believed, when it believed it, and which utterance it came from are all still there.

Three things to know about a round-trip

1. save() rewrites the entities, predicates and atoms tables wholesale, so it is idempotent and safe to call repeatedly; messages are inserted additively and de-duplicated on msg_id. 2. load() expects a fresh Memory — it clears the canonicalizer and ledger before restoring, and rebuilds the message index by re-adding every row. 3. The closed_tx stamp has no column in the schema and is not restored, so known_at-bounded queries do not survive a reload (§05). Valid-time queries, timelines and current values do, exactly.

12Extract

Extractors and adjudicators.

Two separate jobs, deliberately kept apart: an extractor turns raw conversation into claims, and an adjudicator decides whether a novel predicate name means the same as one already stored. A model asked to do extraction and vocabulary management in one pass does neither reliably.

Both are protocols, so anything with the right shape works — a rules engine, a fine-tune, a stub in a test.

python — the two protocols
class Extractor(Protocol):
    name: str
    def extract(self, window: Sequence[Message]) -> list[Claim]: ...


class PredicateAdjudicator(Protocol):
    def __call__(
        self, raw: str, candidates: list[str], value_type: ValueType
    ) -> str | None: ...

An extractor is handed a window of messages, not one message, for two reasons. Pronouns: “she's a cardiologist in Chicago” is unextractable alone and trivial with the previous turn in view. And throughput: one call per window instead of per message is the difference between a 13-hour benchmark run and a 40-minute one.

The implementations that ship:

Shipped implementations, under palimpsest.extract
symbol module what it is
LLMExtractor extract.llm Open-world extractor over a sliding window, backed by any complete_json_many-shaped callable. The model invents whatever predicate name fits and is only nudged toward reusing names it has already used.
LLMAdjudicator extract.adjudicator One batched call per novel predicate, cached in-process by (raw, candidate-set). Refuses any answer that is not literally one of the candidates offered.
DiskCachedAdjudicator extract.adjudicator The same, with decisions persisted to a JSON file. Whether lives_in means city does not change between runs, so a re-run costs zero calls.
StaticAdjudicator extract.adjudicator Deterministic, from an explicit list of synonym sets. Zero LLM calls — for tests and offline runs.
python
from palimpsest import Memory
from palimpsest.extract.llm import LLMExtractor
from palimpsest.extract.adjudicator import DiskCachedAdjudicator, StaticAdjudicator

# fully offline and deterministic
mem = Memory(adjudicator=StaticAdjudicator([{"pet", "animal_companion"}]))

# with a model on the write path
mem = Memory(
    extractor=LLMExtractor(client.complete_json_many, window_size=12, overlap=2),
    adjudicator=DiskCachedAdjudicator(client.complete_json, path=".cache/adjudged.json"),
)
mem.ingest(messages)          # no claims= — the extractor produces them

Do not cache a failed call as a decision

A failed LLM call and a genuine “these are different” both surface as a falsy result. Storing the first as if it were the second permanently teaches the store that lives_in and city are different predicates, after which it serves a superseded value labelled current — the exact failure this engine exists to prevent. LLMAdjudicator distinguishes the two and never caches a failure. If you write your own, do the same.
