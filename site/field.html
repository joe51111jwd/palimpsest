The field

Published numbers in agent memory do not reproduce.

Compiled from primary sources — arXiv full texts, vendors’ own harnesses and committed raw results, the dataset files themselves, and the benchmark repositories’ issue threads. Every claim on this page was checked against an artifact rather than against vendor prose. This is the context any new number has to be read in, including the ones on this site.

01Self-reported

Self-reported scores do not survive independent measurement.

LongMemEval, judged accuracy. “Measured by third parties” means somebody other than the vendor ran the system and published the result.

Self-reported vs. independently measured, LongMemEval
system self-reported measured by third parties
Mem0 94.4 36–67
Supermemory 95 58.4
Zep 90.2 38–64
LightMem the only system whose self-report reproduces

The individual third-party figures behind those ranges, in the order they were published: Mem0 66.4, 64.96, 62.6, 59.8, 53.6, 42.8, 36.0; Zep 63.8, 58.6, 38.3; Supermemory 58.4. Mem0’s headline is roughly 2.6× its median independent score.

LightMem is the exception and deserves to be named as one: its self-report reproduces cleanly under third-party measurement. The point of this page is not that everyone is dishonest. It is that a self-reported score in this field carries almost no information, and there is currently no mechanism that would tell you which ones to trust.

Sources: MemTensor/MemOS_eval_result (cross-vendor re-runs); arXiv 2601.02845, 2511.01448, 2601.02553, 2510.18866, 2605.29640, 2507.05257, 2606.00619, 2602.11182, 2608.03463. Vendor papers: Mem0 arXiv 2504.19413, Zep arXiv 2501.13956.

02Baselines

Two results that question whether memory systems beat tuned RAG at all.

Neither of these is a vendor’s paper, and between them they are the reason this project’s harness runs a hybrid BM25 + dense baseline as a first-class competitor rather than as a strawman.

An embedding swap erases the claim — MemDelta, arXiv 2606.29914

MemDelta rebuilt the baselines Mem0 compared itself against and found the ladder was almost entirely an artifact of baseline quality. Mem0’s advertised +11pp over RAG becomes −1.2pp once the RAG baseline is given a decent embedding model. Nothing about the memory system changed.

MemDelta (arXiv 2606.29914), baseline reconstruction
configuration score
No memory 2.2
Random RAG 3.2
Verbatim RAG, MiniLM embeddings 47.2
Full context 49.8
Verbatim RAG, cloud embeddings 53.4

The gap between the two verbatim-RAG rows is significant at p = .004. Neither row is a memory system.

Construction can destroy accuracy — the LightMem reproduction, arXiv 2607.29104

This reproduction held retrieval fixed at oracle and compared building a memory against not building one: naive RAG 89.0 against LightMem 77.7. Memory construction cost 11.3 points. Break-even against the cost of building the memory arrives at roughly 321 questions.

Independent failure analyses (MemTrace, arXiv 2606.17328; Regimes, arXiv 2606.10241) point the same direction: errors are around 10× more often retrievable-but-unused evidence than genuinely unreachable evidence. The bottleneck is what gets presented to the reader, not what got stored.

The conclusion this project adopts from both: a memory system must be measured against a well-tuned RAG baseline or the comparison is worthless, and it has to justify its construction cost. If the baseline wins a category, that gets published — which is what happened on LoCoMo.

03The dataset

The release everyone cites was deprecated.

xiaowu0162/longmemeval was marked deprecated and replaced by longmemeval-cleaned on 2025-09-19, which “removes noisy history sessions that interfere with the answer correctness”. The _s split changes size; the oracle split is byte-identical. Some vendors report on the cleaned data and some on the deprecated original, and almost nobody states which. Those numbers are not comparable.

Known-bad gold answers survive into the cleaned data. Question 370a8ff4 has a gold answer of “15 weeks” where the evidence supports 11.57; it was reported independently by three groups across five months and is still wrong. Annotation issues remain open on the benchmark repository.

Two eval-code bugs are confirmed. One made recall@all come out at 1.0 because correct_docs was empty, which invalidates every retrieval number published before the fix. Another, still open, silently drops items during expansion resolution. The official tooling also uses two different denominators in two different scripts — one skips 30 abstention items, the other averages over 500.

What this project uses

The cleaned dataset, micro averaging, a judge that is not the answering model, and the unmodified standard Mem0 judge prompt. The dataset file and its hash, the denominator, both models, the prompt and the token budget are printed beside every table on the benchmarks page.

04Labels

The published LoCoMo category labels are wrong on three of four.

The mapping is stated in the LoCoMo authors’ own evaluation code, and it is confirmed empirically by the shape of the data — how many evidence items a question needs, and how often that evidence spans more than one session.

LoCoMo categories, from the authors’ evaluation code and the data itself
cat n mean evidence items evidence spanning >1 session true label
1 282 3.13 95.4% multi-hop
2 321 1.17 8.7% temporal
3 96 2.08 32.3% open-domain
4 841 1.07 0.1% single-hop
5 446 1.03 0.0% adversarial

The Mem0 → Memobase → Backboard lineage uses 1 = single_hop, 2 = temporal, 3 = multi_hop, 4 = open_domain — wrong on three of four. What that lineage reports as “single-hop” is the 282-question multi-hop set; what it reports as “open domain” is the 841-question single-hop set, which is the largest and easiest bucket in the benchmark. Supermemory’s memorybench uses a third mapping and Dakera a fourth. No two vendors’ per-category rows are comparable to each other, and none of them are comparable to the paper.

This site reports the authors’ mapping. Where a competitor’s per-category number is quoted it is relabelled into that scheme and the relabelling is stated. The evidence, with the counts, is repeated in the benchmark methodology.

05Free parameters

Choices that move a score more than any architecture does.

Micro vs. macro averaging

Worth up to about six points on identical data, and almost nobody states which they used. MemOS is 77.8 micro against 80.45 macro. Mastra’s headline 94.87 is a macro mean; its micro figure is 93.60.

The long-context baseline

Spans 14.0 to 82.40 across papers, driven by truncation policy, judge, and model-specific refusal behaviour at long inputs. Any “beats long context by X” claim is unusable without the baseline’s prompt and judge.

Who judges

Several systems are judged by the same model that answered. The highest verified score in the field, LeanMem 91.80, is self-judged. This site’s judge is a separate call and the prompt is the unmodified standard one.

The denominator

Papers report n = 500, 470, 444, 367, 300, 282, 266, 150, 88, 50 and 15 — all of them called “LongMemEval”. Some published arithmetic does not reconcile with any denominator at all.

None of these are exotic. They are the ordinary knobs of running an evaluation, and each one is large enough to manufacture a ranking on its own. That is what makes the field’s numbers incommensurable rather than merely noisy: they are not measuring the same quantity, and stacking them into a comparison table produces a result that means nothing.

06No leaderboard

There is no public leaderboard for agent memory anywhere.

Every vendor publishes its own number, measured its own way, on a dataset version it usually does not name, judged by a model it often does not disclose. There is no neutral board that would make two of those numbers comparable, and no submission standard that would let a stranger re-run either one.

That absence is the reason this project publishes its harness, its raw per-question records, its losses and its own defects rather than a single headline figure — and it is the reason for the leaderboard on this site, which admits a row only if it carries the dataset file and hash, the denominator, both models, the judge prompt, the averaging, the token budget, and the raw per-question results. That rule is applied to this project’s own rows first, and they are marked as the maintainer’s.

Read this with the number

The same standard applies here. On LongMemEval-S — all six categories, 470 questions, ~500 distractor sessions each — this engine is first at 0.536, [0.491, 0.581], and the margin over second place clears an exact paired test (65/35, p = 0.0035). It is the only lead here that ever has. And we lose LoCoMo: full_context 0.549, bm25 0.417, palimpsest 0.408.

Nine defects found in this engine’s own audit are published as well, including one where it could see the future and inflate its own results, and one whose fix lowered the LoCoMo score. The audit is here.
